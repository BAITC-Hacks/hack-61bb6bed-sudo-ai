# План реализации SanaChallenge AI

Основание: `SanaChallenge_AI_HackAlem_A_to_Z.md`. Сначала реализуем бэкенд,
PostgreSQL и бизнес-логику. Исходный документ — описание продукта; примеры
баллов, формулировок и промптов не являются готовыми результатами системы.

## 1. Основа и база данных

- FastAPI, Python 3.12, Pydantic v2, SQLAlchemy Async, asyncpg.
- Слои `api → application → domain`; PostgreSQL и AI — адаптеры инфраструктуры.
- Docker Compose: PostgreSQL 16, миграции отдельным сервисом, backend.
- Alembic: пользователи, команды, участники, навыки, задачи, оценки,
  история ответов и отклики. UUID, внешние ключи, индексы и ограничения.
- Настройки через environment, единые ошибки, health/readiness, CORS, логи.

Критерий готовности: схема создаётся миграцией с нуля; API видит настоящую БД.

## 2. Доменная логика и API

- Черновик, ручное редактирование, публикация, каталог с пагинацией.
- Рубрика качества из 9 критериев на 100 баллов и пять уровней.
- Отклики: один отклик команды на задачу; доступ только своим командам.
- Выбор одной команды бизнесом в транзакции; остальные отклики отклоняются.
- Demo identity из БД: проверяем роль, владельца и членство команды.

Решения для первого этапа: редактируются только черновики; для публикации
нужны title, problem, goal, deliverable, success_criteria и timeline.
Порог рейтинга не блокирует публикацию: исходный документ его не задаёт.
Demo-режим предназначен для локальной разработки, полноценная авторизация —
отдельная задача перед публичным запуском.

Критерий готовности: создать → заполнить → опубликовать → откликнуться →
выбрать; чужие изменения, повторные отклики и двойной выбор блокируются.

## 3. AI Builder

- Async OpenAI, Structured Outputs, ограниченные timeout/retry.
- Структурирование исходной идеи, семантическая оценка, до 3 вопросов.
- Ответы по конкретным полям, улучшение карточки, история рейтинга.
- Финальный балл рассчитывает backend; пустые поля не получают баллов.
- Без AI остаются ручное редактирование и явно обозначенная базовая оценка.
- Внешний запрос не держит блокировку БД; устаревший ответ не затирает правки.

Критерий готовности: ошибки/отказы AI не теряют данные; контракт проверен
тестами. Реальный вызов проверяется отдельно при настроенном ключе и модели.

## 4. Проверки и демонстрация backend

- Unit-тесты рейтинга и matching.
- Интеграционные тесты с PostgreSQL, включая права и конкурирующий выбор.
- Детерминированный seed, инструкция запуска, Swagger/OpenAPI.
- Проверка миграций вверх/вниз, lint и сквозной сценарий.

## 5. Следующие итерации

1. Подключить React/TypeScript к готовому API и пройти сценарий через UI.
2. Проверить реальный OpenAI на синтетических задачах; откалибровать рубрику.
3. Добавить NVIDIA embeddings как заменяемый адаптер; до этого matching
   использует пересечение навыков и явно сообщает способ расчёта.
4. Подготовить настоящую авторизацию, ограничения AI-запросов и deployment.
5. Полировка интерфейса и демонстрации после работающего основного сценария.
